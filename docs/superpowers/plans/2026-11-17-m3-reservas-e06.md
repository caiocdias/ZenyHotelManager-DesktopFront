**Goal:** corrigir os dois achados Importantes da revisão de segurança do intervalo `a300a23..3a50e5c` e os Menores baratos que estão no mesmo código, para a dívida de revisão do processo acelerado ficar paga antes do M4.

**Architecture:**
- **Permissões da área Reservas (`app`):** a leitura das permissões efetivas passa a ser um estado só, `AreaPermissionsState`, com três valores (lendo, falhou, concedidas). A área lê uma vez por sessão e serve os dois usos (as ações do detalhe e a aba de disponibilidade). A falha continua fechada (nenhuma ação, nenhuma aba), mas aparece na tela, com "Tentar de novo".
- **Pendências (`app`):** depois de uma ação, as quatro listas recarregam; o botão "Atualizar" da aba continua recarregando só a lista aberta.

Nenhuma tarefa muda contrato, fronteira entre módulos, dependência ou script de build.

**Tech Stack:** Kotlin, Compose Multiplatform, Gradle; bash (`tests/*.sh`).

## Global Constraints

- **Regras transversais (design §6.2):** nada de JSON ou `code` cru ao usuário; enum extensível tolerado; uma `Idempotency-Key` por intenção; `ETag` e `If-Match` com o `412` tratado; permissões efetivas, com o servidor decidindo; dinheiro em `BigDecimal`; datas de negócio sem conversão de fuso.
- **Preço:** o front nunca calcula preço nem disponibilidade por conta própria. Mostra o que o servidor devolve.
- **Aprovação de superior:** ação recusada com `APPROVAL_REQUIRED` passa pelo diálogo do M1.
- **Dados pessoais:** documento sempre mascarado. Nenhum dado de hóspede em log, em mensagem de exceção ou em cache de disco.
- **Fronteira (ADR 0008):** as features do `app` falam com o servidor só pelo `core`; nenhum `sdk` cru em `app/src/main`.
- **Permissão que falha, falha fechada:** sem a leitura das permissões, nenhuma ação de escrita aparece e nenhuma aba condicionada a permissão abre. Uma leitura de outra sessão nunca vale na sessão nova.
- **Idioma:** a interface e a documentação ficam em pt-BR; o código, em inglês. Os textos de tela deste plano são literais.
- **Testes:** os `*AtaqueTest` e as travas `tests/*_ataque.sh` são do testador, e o desenvolvedor não os edita: se um deles quebrar com a mudança, ele reporta `NEEDS_CONTEXT` com o arquivo e a linha. Antes de alterar um arquivo de teste, o desenvolvedor confere `git log --format='%h %(trailers:key=Soul,valueonly)' -- <arquivo>`: se houver commit `Soul: testador`, a mudança de asserção nesse arquivo é do testador, e ele reporta `NEEDS_CONTEXT`.
- **Verificação da tarefa:** a linha `verificação rápida` do `CLAUDE.md`, com `detektMain` e `detektTest` do módulo tocado. O gate do projeto (`./gradlew build` e `bash tests/run.sh`) roda com o orquestrador, na integração de cada onda.
- **Gradle e commits:** nunca `./gradlew --stop`; se aparecer "daemon disappeared", repita uma vez; commits em pt-BR, com `Soul:` e `Co-Authored-By: Claude <noreply@anthropic.com>` consecutivos no último parágrafo.

## Review Focus

1. **Leitura de permissões que falha não concede nada, nem valor velho.** Depois de uma falha, de uma troca de sessão no meio da leitura ou de uma resposta atrasada da sessão anterior, não há ação nem aba. Testes: `failedReadIsNotAnEmptyGrant`, `lateAnswerAfterCloseIsDropped` (Task 1) e `newSessionNeverUsesThePreviousGrant` (Task 1, na área).
2. **"Tentar de novo" clicado várias vezes não dispara várias leituras.** Testes: `retryIsIgnoredWhileLoadingOrGranted` (Task 1).
3. **Reserva que está em duas listas de pendências some das duas depois de cancelada por uma delas.** Testes: `actionFromPendingTabReloadsTheOtherLists` (Task 2).
4. **Recarregar tudo não lê lista que a aba ainda não abriu.** O guarda `started` de `ReservationsPending` continua: sem a aba aberta, nada é lido. Testes: `refreshBeforeTheTabOpensReadsNothing` (Task 2).
5. **Resultado desconhecido seguido de aprovação cancelada não deixa o formulário travado.** Testes: `cancelledApprovalAfterUnknownResultUnlocksTheForm` (Task 4).

```kotlin
/** A leitura das permissões efetivas da sessão para uma área. */
sealed interface AreaPermissions {
    data object Loading : AreaPermissions
    data object Failed : AreaPermissions
    data class Granted(val permissions: Set<String>) : AreaPermissions
}

/** Lê as permissões uma vez; a falha fica visível e pode ser repetida. Nunca concede sem uma leitura que deu certo. */
class AreaPermissionsState(read: suspend () -> Set<String>, scope: CoroutineScope) {
    val value: AreaPermissions          // estado do Compose; começa em Loading
    fun start()                         // a primeira leitura; chamadas seguintes não leem de novo
    fun retry()                         // só a partir de Failed: volta a Loading e lê de novo
    fun close()                         // a área saiu de cena: cancela a leitura e descarta a resposta atrasada
}

/** O aviso da leitura que falhou, com o botão de repetir. */
@Composable
fun PermissionsNotice(onRetry: () -> Unit, modifier: Modifier = Modifier)
```
